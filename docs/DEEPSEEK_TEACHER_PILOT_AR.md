# MDIA — تجربة DeepSeek OCR كمعلم لـ PaddleOCR

الحالة: تجربة معزولة غير مدمجة في الإنتاج. لا إرسال بيانات ولا تدريب تلقائي.

## الهدف
مقارنة DeepSeek OCR وPaddleOCR على فواتير اصطناعية فقط، والاستفادة من مخرجات DeepSeek لاكتشاف أخطاء قراءة الكلمات والكميات والأسعار. لا تعتبر إجابة المعلم حقيقة مرجعية ولا تسمح بتعديل حقل صحيح.

## قواعد إلزامية
1. لا ترفع بيانات مرضى حقيقية أو مستندات سرية إلى API.
2. لا تستخدم نتائج المعلم وحدها كملصقات تدريب. يجب أن تستند القيم إلى ground truth اصطناعي موثوق، مع ربط صورة المقطع والكلمة والصف والإحداثيات والتحقق منها قبل التدريب.
3. لا تغيير في محرك الإنتاج أو سجلات القبول أو قواعد حساب الفواتير.
4. لا اتصال مدفوع تلقائي؛ تشغيل API يحتاج مفتاحاً وموافقة مستقلة.
5. أي صفحة بها finish_reason=length أو نقص صفحات تُرفض.
6. البيانات المولدة في هذه المرحلة مرشحات اكتشاف فقط وليست بيانات تدريب جاهزة.
7. يحتفظ الاختبار النهائي بعينات لم تدخل التدريب، ويشترط عدم فقد أي حقل صحيح وعدم زيادة الصفوف الوهمية.
8. يظل معيار قبول 300 فاتورة هو 5776/5776 حقلاً صحيحاً، صفر صفوف إضافية، صفر فجوات أدلة، صفر إحالات.

## واجهة API التي تمت مراجعتها
- POST https://api.deepseek.com/v1/tools/ocr
- multipart/form-data: file + purpose=text_recognition
- الإحداثيات المعيارية 0–1000 لمناطق النص؛ ليست إثباتاً تلقائياً لارتباط قيمة بسطر الفاتورة.
- المصدر: https://api-docs.deepseek.com/guides/ocr/

## المرحلة المنفذة في هذا الفرع
أداة محلية للتحقق من استجابة OCR محفوظة وإنشاء manifest مرشحات مقارنة بالقيم الاصطناعية الصحيحة. لا تتصل بالشبكة ولا تستخرج نصوصاً من فواتير مرضى.

مثال:
```bash
python -m unittest tests.test_teacher_labels -v
python -m mdia.teacher_labels --source synthetic.png --truth truth.json --teacher-json deepseek_saved.json --paddle-text paddle.txt --output candidates.json
```

شكل truth.json:
```json
{"synthetic": true, "fields": {"quantity": "٢", "price": "12"}}
```

## الأعمال التالية
1. إصلاح عطل shutil في PR #33 على فرعه بشكل مستقل ثم إعادة خط الأساس.
2. إعداد 30 فاتورة اصطناعية من أصعب الفئات وتسجيل بصمات SHA-256.
3. بعد موافقة مستقلة على تكلفة API، إجراء مقارنة فعلية، وقياس كل حقل وصف ودليل.
4. إنشاء قصاصات صور وتحديد النصوص والصفوف والتحقق من صحتها، ثم تدريب PaddleOCR في فرع منفصل.
5. إعادة اختبار 300 فاتورة وعدم الدمج إلا بعد اجتياز بوابة القبول.

ملاحظة: تحقق ظهور القيمة داخل النص الخام لا يثبت دقة استخراجها أو موضعها أو ارتباطها بالصف. لهذا تعلن الأداة training_ready=false دائماً.
